# How FinalGROM 2.0 works

[Start here](../README.md) · [Build the firmware](building.md) · [File formats](../reference/file-formats.md)

FinalGROM has 1 MiB of cartridge SRAM. The TI reads cartridge data from that memory. An ordinary supported image is loaded before it starts. A prepared image larger than memory keeps its full contents on SD and replaces banks in SRAM as needed.

## The parts and their jobs

| Part | Job |
| --- | --- |
| SD card | Stores images, companion files and card-location indexes |
| AVR microcontroller | Reads files, loads SRAM, handles prepared-bank requests and prepares the menu |
| CPLD programmable logic | Maps TI cartridge accesses to SRAM and carries transfer/control signals and bank requests |
| SRAM | Holds the cartridge bytes the TI can read now |
| Prepared TI program | Requests missing banks and waits from console RAM until the requested bank is ready |

The AVR does not replace SRAM by reading the SD card within each TI bus cycle. SD loading takes much longer. Prepared cartridges contain code that allows the program to wait safely while a requested bank is loaded.

## Starting a prepared cartridge

1. The menu recognizes the GCR/GCS image and opens its matching companions.
2. The loader checks startup data and installs the initial banks. Some banks remain fixed in SRAM; others use a reusable pool.
3. A small TI program, the **launch bridge**, starts from cartridge memory. It restores console scratchpad state, installs a wait routine there, and requests the starting bank.
4. The cartridge begins when its starting bank is ready. Its adapted program and overlays handle later requests.

The [adapter guide](adapters.md#what-is-bridgebin) explains the launch sources. The [player file table](../prepared-cartridges.md#which-files-go-on-the-card) identifies the companions without requiring their byte layouts.

## Loading a requested bank

| Step | What happens | Main implementation |
| --- | --- | --- |
| Request | Prepared TI code moves into safe RAM and commits its bank request. This releases the previous bank reservation. | TI helper and CPLD mailbox logic |
| Find | The AVR finds an already loaded bank, resolves a fixed bank, or starts loading from SD. | `giga-demand.c`, `giga-resume.c`, `giga-fixed.c` |
| Load | Data arrives in 512-byte sectors. Reviewed overlay changes are applied while reading. | `giga-resume.c`, `giga-overlay.c` |
| Resume | The AVR publishes the completed mapping and acknowledges the request. The TI code selects that bank and continues. | `giga-demand.c`, `giga-wire.c` |
| Read ahead | When there is no demand request to service, predicted banks may be loaded early. | `giga-prefetch.c`, `giga-predict.c` |

Predictions are a performance hint. Correctness depends on the request/wait protocol and bank reservations, which protect executing code from replacement. A missing prediction can cause a pause; it must not authorize reading an unavailable bank.

These are cooperative software waits. They should not be described as proof that the cartridge is using the TI READY line to stall every missing ROM access.

## Follow the source

1. [finalgrom.c](../../avr/finalgrom.c) runs the menu/selection loop.
2. [loader.c](../../avr/loader.c) scans folders, builds the menu, and loads ordinary images. It includes session helpers so they can share buffers.
3. [loader-giga.inc](../../avr/gigacart/loader-giga.inc) recognizes prepared images and enters `profile_session()`.
4. [video-session.inc](../../avr/gigacart/video-session.inc) sets up and services that session. `FGVIDEO` selects this path for both video and games.
5. [logic.vhdl](../../vhdl/gigacart/logic.vhdl) implements cartridge mapping, the request mailbox and transfer control.

Use the [cooperative-loader index](../../avr/gigacart/index.md) for individual modules and the [build-support note](building.md#required-build-support) for the retained compilation wrapper. The [AVR](../../avr/index.md), [TI](../../ti/index.md), and [tools](../../tools/index.md) indexes distinguish original files from additions.

## The GROM wrapper

`avr/grom.c` contains generated bytes for the 35-byte menu wrapper assembled from [ti/grom.gpl](../../ti/grom.gpl). It is not a complete GROM emulator; the CPLD implements the bus behavior. The new `giga` modules manage prepared images and loading, rather than additional copies of that wrapper.

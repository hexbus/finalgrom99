# Maintainer reference: development provenance

This page records historical build and archive details for maintainers. It is not an installation guide, and readers do not need the original workspace to use the repository.

The frozen release and the optional local archive serve different purposes. The [125 ms release snapshot](../release/2.0-beta1-125ms/) records the matched AVR, CPLD and menu plus their build inputs and evidence. It is part of the repository. The larger development archive is ignored by Git and is not needed to build the baseline or use the supplied adapters.

## Historical development archive

The October 7, 2026 preservation copy is named `references/legacy-development-20261007/`. It contains earlier Git history, committed and uncommitted work, generated output, toolchains, tester packages, input files and research. Copy verification reports, a Git bundle, staged and working-tree patches, and the original status listing are under `references/preservation/`.

The original workspace, named `finalgrom-gigacart`, was left intact. The directory copy preserves uncommitted and ignored files that the Git bundle alone cannot retain. Both copies were on the same drive when created; this is not an off-device backup.

These paths describe the development archive, not files supplied by a normal clone or patch. On a checkout that has this archive, ignored-file cleanup such as `git clean -fdx` would delete it. Back up the archive separately before cleanup or relocation.

## Release and cartridge provenance

The frozen baseline corresponds to tester R4 and private-testers R2. [Release provenance](../release/2.0-beta1-125ms/provenance.json) records the firmware/menu identities compared with both tester archives. Later recipe and package work does not modify that snapshot.

The original six cartridge examples came from private-testers R2, under `03-CARTRIDGES/BETA20`. Their image and companion hashes were checked against the [six-set audit](../release/2.0-beta1-125ms/evidence/imported/tool-audit/current-six-companion-rebuilds.json) on 2026-10-13. Dragon's Lair was added separately from the archived `copy-queue/DRAGON.GCS` and `cooperative-v23a/3-carts` companions; the [additional audit](../templates/gigacart/beta1/additional-companion-rebuilds.json) retains those locations and hashes. All seven examples reproduced their reference companions byte for byte.

An earlier tested SD copy named the same Dragon image bytes `DRAGON.GCR`; the supplied example uses `DRAGON.GCS`. The launch-bridge sources were recovered unchanged from the archive. Their binaries were extracted from verified GLP files and reproduced from source on 2026-10-13. These are file-identity checks, not new hardware tests.

The [historical package index](../templates/gigacart/beta1/packages.json) records locally verified `2.0-beta1-125ms-prepared-r3` ZIPs. R3 added Dragon's Lair to the original six sets; R1/R2 and the frozen firmware snapshot were retained unchanged. No public URLs are recorded. Those ZIPs predate later documentation edits, so their hashes do not identify packages rebuilt from current guides. Use the index generated by each new packaging run.

The startup-delay baseline was distributed as tester R4 and private-testers R2, superseding tester R3 and private-testers R1. The AVR startup delay changed; the CPLD was identical between those revisions. A previously tested mail-format patch reproduced its committed AVR/menu in a fresh upstream checkout using `core.autocrlf=false` and `git am --keep-cr`. That historical result does not validate later uncommitted changes.

## Lion King research

Lion King experiments are maintained separately in `finalgrom-lion-king-research`. At preservation time, that repository's ignored archive path was a junction to this archive. Experiment source, issued-trial inputs and selected evidence were tracked there; the original 512 MiB image and historical generated packages remained outside patch history.

The recorded research status was short playback working, with startup, complete playback and portability unresolved. The 125 ms firmware baseline excludes those experimental session changes. Consult the research repository for subsequent results.

## Reference repository

The October 13, 2026 cleanup moved **43 source files**, the former AVR legacy index and four audit files out of the maintained tree. They are preserved in the separate local Git repository **`finalgrom-2.0-reference`**, located at `E:\git\finalgrom-2.0-reference` on the originating workstation. Its `REFERENCE.md` is the entry point. A normal firmware build does not need that repository.

The reference repository contains a hash-verified snapshot of 361 files, including uncommitted work as it existed before cleanup. Snapshot commit `b44addde7c13b435ea0b4d7544e4aef3aa3ef006` preserves the original source paths and build tools; a later commit records the moved originals under `relocated/`. The [archive manifest](../results/reference-archive-20261013.json) records the repository commits, relocated paths and hashes, retained source edits, and validation results. The source snapshot and relocated copies are both preserved. This is a local repository, not an off-device backup or published remote.

The moved sources comprise all 18 files in `avr/legacy/`, five added AVR diagnostics, fifteen older AVR root files and five TI programs. The reference snapshot also preserves the original `results/legacy-exclusion-20261013/` directory, with all twelve audit results, the exclusion manifest, experimental patch and reproduction script. Those filenames describe the completed experiment; they are not active build dependencies.

The maintained source tree uses the separate [build recipe](../tools/firmware-build.json), with 70 staged inputs and 19 compilation units. It has no path or symlink to the reference repository. The frozen release manifest and its original 113-input recipe remain unchanged as evidence.

## Legacy exclusion audit: October 13, 2026

| Isolated build | AVR result |
| --- | --- |
| Unchanged baseline | Exact match: 28,428 bytes. |
| Exclude the C implementations in `avr/legacy/` | Exact match. |
| Exclude all 18 legacy files and the sample-helper include | Compile failure: unused compilation code still calls `cinema_sample()`. |
| Also remove the unused native-compilation routine and its loader helper | Exact match with all 18 files absent. |
| Exclude 42 files, retaining both trimmed session includes | Exact match. |
| Exclude 43 files, retaining either one of those includes | Both alternatives match; the retained choice is `compilation-session.inc`. |
| Exclude all 44 candidates, retaining only the shared sector writer | Builds to 28,416 bytes; does not match Beta 1. |

The integrated 43-file variant changes three retained source files: remove the regular-session include, remove the Cinema sample include, and trim the unused native-compilation functions and their header dependency. The shared `offline-sector.inc`, `sd-receive.inc` and `giga-cache.h` remain required. Original versions of every changed file are preserved in the reference snapshot.

Removing both session includes changes function layout and generated code. Compiler optimization/layout effects are the likely explanation; functional equivalence of that different binary was not established.

### Compilation session retention decision

**`avr/compilation-session.inc` remains active, classified as required build support for exact Beta 1 reproduction. It was not archived.** The implemented cleanup trims only its obsolete native-compilation routines and header dependency. It preserves `prepareCompilation()` and the shared sector writer include.

Follow-up isolation showed that retaining just `prepareCompilation()` restored the exact bytes, while removing that wrapper changed the binary. The wrapper itself was absent from emitted machine code in both cases. This establishes build significance, not runtime execution or a demonstrated behavior change. The exact compiler decision remains unresolved.

### Verification and archival boundary

The reference snapshot was verified and committed before any source was moved. Each of the 48 relocated files was checked against its captured SHA-256 before moving. The [archive manifest](../results/reference-archive-20261013.json) retains the complete inventory and build results.

The maintained AVR target remains `041bd157a71deeb9141e676ea945a940e8a011fb8e9d5a674ec0eeb40118849f`; the menu target remains the frozen 2,310-byte `FGMENU.BIN`. The verification record distinguishes rebuilding those files and the seven bridges from merely checking CPLD hashes. No fresh CPLD fit or hardware test is claimed.

Original upstream bootloader, JTAG, library, examples, tests and utilities remain in the maintained tree. Current cartridge adapters, templates, recipes and prediction tools remain. The SD prototype, its instruction tests and results are preserved with their matching build inputs under `research/sd-pipeline-20261013/` in the reference repository; they are excluded from the Beta 1 branch. Existing ignored development archives and build outputs were preserved; they are outside the patch and are not read by the maintained build.

### Reproduce the archived audit

In the reference repository, use its captured build tools with AVR GCC 15.2.0 and matching binutils. Replace the example xdt99 path and choose a new output directory:

```powershell
python results/legacy-exclusion-20261013/reproduce.py --output output/legacy-audit-check --xdt99 C:/tools/xdt99
```

This command belongs to the reference checkout. The script rebuilds the pre-cleanup source set and twelve variants, including the expected compile failure and two nonmatching builds. For current firmware, use the [maintained build guide](building.md); no archived source is required.

# How the FinalGROM 2.0 firmware fits together

FinalGROM has 1 MiB of cartridge RAM. A 128 MiB image cannot fit there at once. This firmware keeps selected banks in RAM and loads other banks from SD when a prepared cartridge requests them. The cartridge waits in console RAM until its requested bank is ready.

This is the current **cooperative loading** design. It requires prepared cartridge code and companion files. It does not turn every unmodified Gigacart image into a working FinalGROM image. Supported behavior and omissions are maintained in [release notes](release-notes.md); file formats are maintained in [cartridge formats](cartridge-formats.md).

The [AVR index](../avr/index.md), [TI assembly index](../ti/index.md) and [tools index](../tools/index.md) identify upstream files, later additions and their build roles.

## Start reading here

1. [finalgrom.c](../avr/finalgrom.c) runs the menu/selection loop and dispatches the selected cartridge.
2. [loader.c](../avr/loader.c) scans SD directories, builds the menu and loads ordinary cartridges. It includes the large-cartridge and compilation session code so they can share its small memory buffers.
3. [loader-giga.inc](../avr/gigacart/loader-giga.inc) recognizes large-image selections and enters `profile_session()`.
4. [video-session.inc](../avr/gigacart/video-session.inc) sets up the current cooperative session and runs its service loop. This is the shared prepared-cartridge path for video and games.
5. [logic.vhdl](../vhdl/gigacart/logic.vhdl) implements the CPLD side: cartridge mapping, the request mailbox and transfer control.

The `FGVIDEO` build flag selects this cooperative session for both video and game cartridges.

## What happens when a bank is needed

| Step | What happens | Main source |
| --- | --- | --- |
| Prepare | Open the image and companions, validate startup data and install initial banks. | `video-session.inc`, `giga-launch.c` |
| Request | Prepared TI code enters safe RAM and commits a bank request to the CPLD mailbox. This releases its previous bank reservation. | Cartridge helper and CPLD logic |
| Find or load | Reuse a ready bank, resolve a fixed bank, or load a missing bank in 512-byte sectors. Apply the prepared overlay while reading. | `giga-demand.c`, `giga-resume.c`, `giga-overlay.c` |
| Resume | Publish the completed mapping and acknowledge the request. The TI helper can select that bank and resume. | `giga-demand.c`, `giga-wire.c` |
| Read ahead | When no request needs service, optionally load predicted banks while protecting the bank still in use. | `giga-prefetch.c`, `giga-predict.c` |

Prediction improves loading opportunities; it does not establish that a bank is safe to replace. The explicit request/wait protocol and bank reservations provide that protection.

## Where the current large-cartridge code lives

The [cooperative loader index](../avr/gigacart/index.md) lists every module, header and session helper with its responsibility. Headers define the interfaces and safety requirements. The session `.inc` files join these modules to the loader's shared buffers.

`avr/compilation-session.inc` is **required build support for exact Beta 1 reproduction** and remains in the active sources. Only its obsolete native-compilation routines and header dependency were trimmed; the build-significant wrapper remains. See the [retention decision](preservation.md#compilation-session-retention-decision).

## Earlier approaches and diagnostics

Earlier controllers and diagnostics are preserved in a separate [reference repository](preservation.md#reference-repository). The maintained build excludes them and compiles 19 translation units while reproducing the released AVR bytes. Historical diagnostic flags are outside this maintained configuration.

The frozen recipe records the older input set for provenance. The current [build recipe](../tools/firmware-build.json) is self-contained and does not fetch archived files. **Build significance and runtime execution remain different things**, as the retained compilation wrapper demonstrates.

## Why the original grom.c is different

`avr/grom.c` contains generated bytes for the 35-byte menu wrapper assembled from [ti/grom.gpl](../ti/grom.gpl). It is not a complete GROM emulator. The CPLD implements the bus behavior. The new `giga` modules handle large-image storage and loading; they are not additional copies of that menu wrapper.

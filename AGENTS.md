# Repository working instructions

README.md and docs/ are the canonical documentation. Keep one authoritative home for each fact and link to it. Preserve evidence labels, assumptions, and unresolved contradictions.

Do not describe host simulation as a hardware measurement. Keep user-supplied compatibility inputs and pinned upstream sources unchanged; place new work outside those snapshots. Do not flash hardware unless the user has explicitly authorized that device operation.

Write public documentation for someone using a fresh clone without access to the development conversation or local workspace. Keep personal paths, internal package history and archive details out of task instructions; retain necessary historical evidence in docs/preservation.md, clearly labeled as maintainer reference. Explain required inputs and use clearly marked example paths.
